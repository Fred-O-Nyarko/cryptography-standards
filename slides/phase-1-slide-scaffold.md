# Cryptography Learning App: Phase 1 Slide Scaffold

This scaffold mirrors the in-app `/present` route. It is intentionally a Phase 1
deck outline: classroom-ready structure first, algorithm-specific internals later.

## Slide 1: Cryptography Techniques: Interactive Learning Journey

- Cybersecurity class project covering DES, 3DES, AES, RSA, ElGamal, and ECC.
- Phase 1 proves the experience model before algorithm-specific internals are added.

## Slide 2: Learning Journey

- Concept first: what the algorithm is trying to achieve.
- Math second: the formal model needed to reason rigorously.
- Process third: key generation, encryption, decryption, and security context.

## Slide 3: Algorithm Map

- Symmetric: DES, 3DES, AES use shared secret keys and block-cipher thinking.
- Asymmetric: RSA, ElGamal, ECC use public/private key pairs and hard math problems.

## Slide 4: Symmetric vs Asymmetric

- Symmetric cryptography is efficient and depends on shared-key handling.
- Asymmetric cryptography solves different key distribution problems but is mathematically heavier.

## Slide 5: Interactive Demo Placeholder

- The toy block visualizer validates step controls, bit grids, reduced motion, and explanation panels.
- Future phases replace toy data with real algorithm-specific demonstrations.

## Slide 6: Reference Backbone

- Standards and primary papers are tracked inside the app from the start.
- Each future algorithm lesson can cite its source material at the section level.

## Speaker Notes

- Do not claim the toy visualizer is DES, AES, RSA, ElGamal, or ECC.
- Emphasize that Phase 1 builds the teaching infrastructure and academic source model.
- Use `/present` for live classroom delivery and `/references` for source credibility.
